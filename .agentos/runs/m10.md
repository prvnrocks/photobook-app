## Recommendations
- **Shapes**: CSS `clip-path` (circle/ellipse/polygon) for every geometric slot. It stays a vector clip, the JPEG passes through untouched, and it costs about 1 KB.
  For non-polygon shapes (heart, blob) use CSS `clip-path: url(#id)` pointing to one shared inline `<svg><clipPath clipPathUnits="objectBoundingBox">`; this is just as clean.
  Rounded slots: `border-radius`.
- **Frames/shadows: use (a) `box-shadow`** on the rotated frame element. Shadow = 300 dpi gray soft mask (about 20–30 KB per framed photo); the photo stays DCT at full dpi
  and the caption stays live text. (c) a pre-rendered PNG is equally clean (about 14 KB) but needs an asset per frame aspect/size, so keep it only as a fallback.
  **Never use `filter:` (drop-shadow, blur, or any CSS filter) on anything that contains a photo or text in print.** Chromium rasterises the whole subtree:
  photo re-encoded to Flate at 300 dpi, about 2 MB per photo, caption no longer text. Add a test or lint guard for `filter` in print markup.
- **Stickers**: own SVGs, either inline `<svg>` or `<img src=.svg>`. Both stay vector (img gives a Form XObject + transparency group when the SVG uses opacity).
  Prefer inline or a sprite (`<use>`) so editor/viewer/print share markup. Avoid SVG `filter` elements inside stickers (same rasterisation risk, not tested).
- **Tape**: an rgba fill + rotate is vector with ca alpha. Skip the tape's own box-shadow, or keep it tiny (it adds a small raster mask).
- **Textures**: tile with `background-repeat` + `background-size: 40mm`. That gives a tiling Pattern with the JPEG embedded once at 325 dpi.
  Wash with `background-size: cover` gives DCT passthrough at 150 dpi (matches A5). Both are fine.
- **Veil**: rgba(255,255,255,.75) overlay is a plain vector fill with constant alpha. No transparency group, no rasterisation. A photo used twice on a page is embedded once.
- **Transparency in general**: the output uses constant alpha (ca), luminosity soft masks and one transparency group. That suits a PDF/X-4-style workflow but not PDF/X-1a (which has no transparency).
  Confirm with the print partner in phase 2.
- **Fonts**: ship the 10 static files above (Cormorant italic optional) through next/font/local in print-fonts.ts, with unique `print*` const names (lesson).
  **Every font-family chain must include an Arabic face** (script → Aref Ruqaa, display → Lalezar, serif → Amiri), and put a final static fallback face in the chain for
  symbols. Otherwise Chromium uses system fonts: on macOS that gave LucidaGrande as **Type3**, and on the Vercel @sparticuz/chromium image there may be **no Arabic system font at all (tofu)**.
  Avoid "→"-type symbols in templates, or check coverage with the cmap. Bebas Neue maps lowercase to caps glyphs (by design).
